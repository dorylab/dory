# Agent が SQL を書き始めた今、必要なのは単なるデータベース MCP サーバーではない

[English](./product-positioning.md) | [简体中文](./product-positioning-cn.md) | [Español](./product-positioning-es.md) | [日本語](./product-positioning-jp.md)

> **Dory is an AI-native SQL client for humans and agents. Query, explore, visualize, and open agent database work as editable SQL workspaces.**

これまで、SQL クライアントは人が使うものでした。人がデータベースに接続し、Schema を読み、クエリを書き、結果を確認し、得られた知見をチャートやレポートにまとめてきました。

いま、そのワークフローに Agent が加わり始めています。Agent は質問を理解し、データベースの構造を探索し、SQL を生成して、以前なら何度もの手作業が必要だった分析を数分で進められます。しかし、ここには新しい問題があります。Agent の仕事がチャット画面に残された SQL の断片と数行の結果だけで終わるなら、それは依然として使い捨ての回答であり、レビューして続けられるデータ作業ではありません。

Dory は、この問題を解決するために作られています。

Dory は、人と Agent のための AI-native SQL Client です。開発者、データアナリスト、データエンジニアが日常的に使う SQL ワークスペースであると同時に、MCP を通じて Codex CLI や Claude Code などの Agent にデータベース作業レイヤーを提供します。

一般的なデータベース MCP サーバーと異なり、Dory はクエリを実行して結果を返すだけではありません。Agent の作業を、実体のある編集可能な SQL Workspace に変換します。人は Agent が作成した SQL タブを開き、実際に実行された文と ResultSet を確認し、フィルターやチャートを検証し、クエリを修正して、同じコンテキストから作業を続けられます。

## Agent が渡すべきものは、回答ではなく作業そのもの

実際のデータ業務では、答えを得ることは多くの場合、始まりにすぎません。

Agent がどのテーブルを使い、各カラムをどう解釈し、どの SQL を実行したのか。結果は完全なのか。JOIN、フィルター、集計に誤りはないのか。問題が見つかれば、SQL を編集して再実行し、結果を比較し、チャートを作成し、データをエクスポートするか、有用なクエリを保存する必要があります。

このプロセスがチャット履歴の中にしか存在しないと、人は Agent、データベースツール、ドキュメントの間で内容を何度もコピーすることになります。実行コンテキストは簡単に失われ、結果はそれを生成した SQL から切り離され、次の担当者は分析を最初から再構築しなければなりません。

Dory はこれらの作業を Agent Run にまとめます。Agent Run はデータベース作業の継続的なコンテキストであり、接続情報、Schema の探索、SQL タブ、クエリ結果、チャート、Saved Queries、実行タイムラインを保持できます。Agent がそこで作業を始め、人はいつでも同じワークスペースを開いて引き継げます。

Agent の成果は、続きのないメッセージではなくなります。確認し、編集し、再利用できる仕事として残ります。

## 1 回のクエリを、引き継げる SQL Workspace へ

あるプロダクト指標が最近変化した理由を調べたいとします。

Agent は Dory を使って利用可能な接続を一覧し、関連する Schema を探索し、テーブルと関係を確認したうえで、仮説を検証する読み取り専用 SQL を実行できます。各クエリでは SQL と ResultSet がひとまとまりで保持され、切り詰められた回答だけがチャットに返されることはありません。

その後、人は Dory で Agent Run を直接開き、次の作業を行えます。

- Agent が実際に使用したテーブルやフィルターを確認する
- 複数のクエリが生成した本物の ResultSet を検証する
- SQL を編集し、同じタブで再実行する
- 返されたデータを検索、並べ替え、フィルタリングする
- 棒、折れ線、円、散布図、ヒストグラム、ヒートマップとして可視化する
- 結果をエクスポートするか、クエリを再利用できる形で保存する

チャットから別のクライアントへ SQL をコピーする必要も、次の共同作業者にコンテキストを一から説明し直す必要もありません。人と Agent は同じデータベース機能を使い、同じ作業を扱います。

## AI-native とは、SQL を隠すことではない

多くの AI データ製品は、SQL を見えなくしようとします。しかし Dory は、SQL こそ人と Agent の間にある最も重要な協働インターフェースの一つだと考えています。

自然言語は目的を伝えるのに適しています。一方、SQL は何が実行されるのかを正確かつ検証可能な形で示します。本当に AI-native な SQL Client は、もっともらしい回答で SQL を置き換えるべきではありません。Agent が SQL を効率よく生成、整理できるようにしながら、人がそれを確認して変更できる状態を保つべきです。

そのため Dory の AI Assistant は、実際のデータベース Schema と現在のタブのコンテキストを使って動作します。自然言語から SQL を生成するだけでなく、既存のクエリを説明、書き換え、修正できます。AI はデータベース作業の外に浮かぶチャットボックスではなく、人が実際に使う SQL Workspace の中で働きます。

Dory の Schema Explorer も同じ協働モデルを支えます。人はテーブル、カラム、データベースオブジェクトを閲覧し、リレーションシップグラフから主キー、外部キー、テーブル間の関係を理解できます。Agent も MCP 経由で同じ Schema を探索し、実際の構造に基づいてクエリを構築できます。グラフは検索、自動レイアウト、PNG または SVG へのエクスポートに対応し、初めて見るデータベースも理解しやすく、共有しやすくします。

## Agent に能力を与えながら、明確な安全境界を保つ

Agent をデータベースに接続することは、コントロールを手放すことではありません。

Dory は Agent に明示的な読み取り専用 SQL ツールを提供します。Agent は接続の一覧、Schema の探索、テーブルのプレビュー、Saved Queries の読み取り、読み取り専用分析を実行できます。Dory のリソースを作成、更新、削除する操作には、独立した書き込み権限と明示的な承認が必要です。

Schema Compare も同じ原則に従います。カタログメタデータを読み取り、PostgreSQL、Neon、Supabase、MySQL、MariaDB、SQLite、Cloudflare D1 など、同じ方言ファミリーに属するデータベース同士を決定論的に比較できます。テーブル、カラム、インデックス、制約、ビューの変更を特定し、リスク評価の根拠を記録します。アプリケーションの行データを読み取ることも、マイグレーション SQL を生成することも、接続先データベースを変更することもありません。

安全性は「AI が注意してくれる」という約束に依存すべきではありません。人が理解し、設定できるプロダクト上の境界として実装されるべきです。

## 1 つのプロダクト、複数の使い方

Dory は PostgreSQL、ClickHouse、MySQL、MariaDB、SQLite、DuckDB、Cloudflare D1、Neon、Supabase、SQL Server、Oracle、Snowflake をサポートしています。ClickHouse にはさらに、クエリ監視、スロークエリとエラーの分析、ユーザーとロールの管理、クラスターレベルの権限操作といった、より深い運用機能を提供します。

Dory は Desktop アプリとして利用できるほか、Web 版をセルフホストできます。`@getdory/cli` は stdio または HTTP で MCP を公開できる Standalone Headless Runtime を提供し、既存の Dory Web 環境は Hosted Bridge を介してローカル Agent に接続できます。

これにより、Dory は開発者のローカル環境、データチームの共有サービス、セルフホスト基盤、自動化ワークフローに導入でき、どの形でも同じ SQL Workspace とデータベース機能を維持できます。

Dory は Apache-2.0 ライセンスのオープンソースソフトウェアです。データベースツールの次の進化は、人をワークフローから外すことではありません。人と Agent が、同じ可視で編集可能な、継続性のあるワークスペースで協働できるようにすることです。

AI-native SQL Client の価値は、人から SQL を隠すことではありません。Agent のデータベース作業を、人がレビューして続けられるプロセスへ変えることです。

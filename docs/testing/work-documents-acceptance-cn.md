# Markdown Work 使用说明与验收

日期：2026-10-23。Work 是独立保存的分析报告；Agent Run 继续表示分析执行记录。

## 使用方式

1. 从组织级 Data Agent 选择数据源，或从数据源内进入并预选当前连接。多源分别执行只读查询，不跨源 SQL 联查。普通问答留在聊天中，要求报告时创建 Work。
2. Work 正文以 Markdown 为唯一保存格式。默认在排版后的文档中编辑，工具栏支持标题、强调、列表、引用、链接、代码和简单表格；可切换 Monaco Markdown 源码。
3. 文档和源码切换本身不保存、不生成版本。不能无损转换的源码保留原文，并提示使用源码模式；原始 HTML 作为文字显示，不执行脚本或 MDX。
4. 查询结果使用只读图表、表格和指标卡片，通过拖动手柄移动，或删除卡片。来源链接和卡片的证据按钮打开侧栏，查看 SQL、执行时间、结果预览及 Knowledge 快照。
5. 停止编辑后自动保存，完成后可以让 Agent 继续分析。每个保存版本包含同一份 Markdown、可视化配置与证据快照。版本恢复创建新版本；并发冲突保留编辑内容并拒绝覆盖。
6. HTML、打印／保存 PDF 与页面阅读使用同一正文和资产解析器。Markdown 导出为 ZIP，包含 report.md、相对路径 SVG 图表和 Markdown 结果表。默认不输出证据 SQL，图表不依赖网络资源。
7. Work 列表支持搜索、数据源筛选、重命名与归档。已验证查询或选中的业务定义可经人工确认加入 Knowledge。

## 模型与保存协议

- `content` 只有 `markdown`、`visuals`、`evidence`、`knowledge`；编辑器内部 JSON 不持久化。标题、分析范围、状态和版本仍是元数据。
- 可视化引用：`![标题](dory://visual/visual-id)`；证据引用：`[来源](dory://evidence/artifact-id)`。每个可视化引用真实 Artifact，指标引用真实结果单元格。
- Agent 创建 Markdown 草稿；更新前读取最新文档，再提交 `expectedRevision` 和唯一匹配的 `oldText/newText`。缺失或重复匹配、损坏引用、未知资产、范围外证据和版本冲突都拒绝写入。
- 更新中的 `visuals` 按 ID 增量写入；未修改配置自动保留，正文不再引用的配置自动清理。正文与资产在同一次保存中形成版本。
- 本地模型通过已有 `dory_finish_work` 的 report 字段创建、读取、局部修改。`read:true` 只读取最新正文和版本，不保存、不结束运行；没有新增外部 MCP 报告工具。
- 创建使用稳定请求键去重；失败保留当前文档。草稿不能被标记为已完成分析，完成报告必须包含正文。已有完成报告不会被未完成刷新覆盖。
- 快照最多保留每份证据 500 行、整份报告 4 MB。报告阅读不重新查询数据源；重新分析仍需要有效权限、连接与模型。
- 这是未发布产品的直接改造，删除旧 blocks 接口和表单编辑方式，不提供旧报告转换、双格式读取或兼容分支。

## 验证范围

- 浏览器回归：文档／源码实际编辑、模式切换、基础格式往返、可视化引用、自动保存、恢复、HTML 导出、窄屏深色主题，以及不支持源码的无损保留和 HTML 不执行。
- 服务与持久层：PGlite 和 Postgres 的私有隔离、创建去重、并发版本比较、快照保留、恢复、归档；真实服务验证局部文本修改、人工内容保留、资产增量更新、失效结果处理、未完成刷新拦截和本地模型读取协议。
- 共享应用覆盖 Web 与 Desktop 服务路径。沿用共享运行时辅助层与 Electron 注入配置，没有新增散落的运行时判断。未进行 Electron 打包安装或原生打印窗口操作。
